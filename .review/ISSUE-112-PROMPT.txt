## Required design points

### `core.entity_links` table

Columns (mirror docs/design/11-entity-linking.md §"Data Model Draft" + add the lifecycle status):
- `id uuid pk default gen_random_uuid()`
- `workspace_id uuid not null` (FK → `core.workspaces.id`)
- `source_type text not null`, `source_id uuid not null`
- `target_type text not null`, `target_id uuid not null`
- `relation_type text not null`
- `visibility text not null default 'internal_only'`
- `status text not null default 'active'` — enum domain `active|stale|detached|revoked` (only `active` is produced by this slice; `stale` populated later by Slice 7, others by #113)
- `managed_system_id uuid not null` (denormalized for filtering/audit/default visibility; NOT the authority for target permission)
- `created_by uuid not null` (FK → `core.actors.id`), `created_at timestamptz not null default now()`
- `updated_at timestamptz` (nullable until first transition; reserved for #113)

Constraints + indexes:
- CHECK constraints on enum domains (relation_type ∈ {'related_to'} for now — extensible later; visibility ∈ the 4 spec tokens; status ∈ the 4 lifecycle tokens; source_type/target_type in a small allowed set including at least 'voc')
- Unique partial index `(workspace_id, source_type, source_id, target_type, target_id, relation_type) WHERE status='active'` — prevents duplicate active links
- Composite indexes `(workspace_id, source_type, source_id) WHERE status='active'` and the symmetric `(workspace_id, target_type, target_id) WHERE status='active'` for fast lookup from either endpoint (FR-LINK-003 will reuse these)
- `(workspace_id, managed_system_id, status)` for the audit UI later
- GRANTs: `fops_app` gets INSERT + SELECT (UPDATE deferred until #113 needs it; DELETE never — no hard delete)

### `POST /entity-links`

Request DTO: `{ source: {type, id}, target: {type, id}, relation_type, visibility? }`. In this slice the server REJECTS anything other than `source.type='voc'`, `target.type='voc'`, `relation_type='related_to'`, `visibility ∈ {undefined, 'internal_only'}` (default `internal_only`). Reject self-link (source equals target).

Authorization (the heart of the tracer):
- Look up source VOC and target VOC (per-type resolver pattern — register a `voc` resolver that returns `{workspace_id, managed_system_id}` or 404).
- Both rows MUST be in the actor's workspace; cross-workspace = 404 (do not leak existence).
- Actor MUST have the existing VOC-read capability on BOTH `managed_system_id`s (reuse whatever permission helper the VOC read path uses today; if VOC routes use a `requireMSScope` middleware, use the same).
- If either check fails on the target, return 404 (not 403) — do not leak that the target exists.
- Set `entity_links.managed_system_id` to source's `managed_system_id` (denormalized).

Side effects: emit audit_log event `entity_link.created` with payload `{ link_id, source, target, relation_type, visibility }`. Wrap insert + audit in a single transaction.

Idempotency: NOT required in this slice (no Idempotency-Key contract). The unique partial index handles double-clicks; on conflict, return the existing active link with 200 (or 409 — pick one and stick with it, document in DEVIATIONS if you pick 409).

### `GET /entity-links`

Query: `?source_type=voc&source_id=<uuid>` (the VOC detail tab consumer's shape). MAY also accept `?target_type&target_id`. Returns active links the actor may see.

Visibility decision: for each link the actor would otherwise see, check the actor's scope on the OTHER endpoint's `managed_system_id`. If the actor has scope → emit the row with `visibility_state: 'allowed'`. If not → emit a stub row with `visibility_state: 'hidden'` carrying only `{id, source_type, target_type, relation_type, visibility_state}` (NEVER `source_id`/`target_id` of the hidden side, NEVER any synthesized summary). This is the FR-LINK-002 contract surface for this tracer.
