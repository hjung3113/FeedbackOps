1. 요약

전체 인상: AppShell, spacing, border, modal 문법은 비교적 안정적이다. 더 큰 문제는 정보구조와 상태 표현의 계약이 surface별로 끊기는 것이다. VOC/Triage는 440px panel 안에서 nav·채널·composer·action이 중첩되고, Home은 0건 queue도 actionable queue와 같은 시각 무게를 가진다.

가장 먼저 고칠 것은 미세한 미감이 아니라 오해를 만드는 UI다: Managed System selector의 실제 적용 범위, VOC ‘다음 액션 없음’ 모순, Permission default Approve, Integration ‘Action dashboard’ redirect.

공통 컴포넌트에서는 status contrast와 RGB triplet token 소비가 전역 영향 문제다.

근거:

manifest 73 entries / screenshots 69.

Finding/Task Request detail은 실데이터가 없어 live 미확인. Survey Results는 0-response만 확인.

Integration Evidence/Coverage는 실제 Not Found이며 시각 문제보다 구현 coverage gap으로 분리했다.

2차 검토 기준: “그냥 안 예쁨”보다 잘못된 상태를 말하거나 컨트롤이 실제 동작 범위보다 더 큰 의미를 암시하는 문제를 상위로 올렸다.

4. 제안 규칙 초안

  1. 전역 scope selector는 현재 route query에 실제 적용될 때만 interactive.
  2. Detail panel top nav 최대 5개.
  3. Anchor nav와 mode tab을 같은 문법으로 겹치지 않음.
  4. 한 row semantic color 기본 2종 이하.
  5. Sticky primary CTA는 panel당 1개.
  6. Empty/Error/Permission은 title+reason+next action/retry contract.
  7. Raw UUID 사용자-facing 기본 노출 금지.
  8. 12px 이하 text는 실제 합성 background 기준 AA 자동 검증.
  9. RGB triplet raw token 직접 CSS color 참조 금지.
  10. 0-count queue는 actionable queue보다 낮은 visual weight.

6. 한 번 더 엄격하게 검토한 결과

  • VOC/Triage nav 과밀은 실제 1440 캡처에서 마지막 항목이 잘리므로 취향 문제가 아니다.
  • Managed System selector는 단순 일관성 문제가 아니라 scope 오인을 만들 수 있어 HIGH로 승격했다.
  • VOC ‘다음 액션 없음’ + CTA 동시 노출을 별도 HIGH로 분리했다.
  • ReporterStatusBadge contrast는 실제 token/tint 합성값으로 8상태 중 6상태 AA 미달을 재계산했다.
  • Severity raw-token 결함은 소스로 확정되지만 현재 Finding/Task consumer live data가 없어 시각 증거 범위를 제한했다.
  • radius/shadow, Survey create modal field 수, Analytics Area overlay 방식 등 취향 개입이 큰 항목은 핵심 이슈에서 제외했다.
