Adversarial Review — Multi-Agent Workflow

목적: 치명적 실패 가능성 사전 색출. Codex × Claude 양측 적대적 분석.
2026-05-23 · transcript pane: workspace:11 / surface:75

⚠ Top 3 Ship-Blockers (배포 전 반드시 해결)

  1. 병렬 cluster의 semantic 충돌 — 각 PR 통과해도 머지 순서가 망친다. .review/ 만으론 못 막음. 해결: 모든 cluster는 머지 직후 develop 재베이스 + affected 전체 테스트 강제.
  2. 책임 공백 (REVIEWER/VERIFIER split → 통합동작 누구도 안 봄) — 각 역할 green인데 합치면 안 됨. 해결: Release Captain 1명 (CONDUCTOR가 겸임 가능) 명시. green artifact 있어도 reject 권한.
  3. Workflow tax > 구현 속도 (아이러니 실패) — 모든 변경에 5 역할 강제하면 user 의도 정반대. 해결: P3 trivial는 CODEX + VERIFIER 2 역할만. 전체 cluster는 migrations/auth/shared UI/permissions/prod data path에만.

CODEX 적대적 분석 7 risks (severity × likelihood)

1. 병렬 agent가 공유 가정 오염CRIT-1
WHAT BREAKS
CODEX cluster들이 stale context로 adjacent contracts/tests/mocks/fixtures/migrations 편집. 각 PR 단독 통과 → 머지 순서가 prod 깨뜨림.
WHY DESIGN FAILS
.review/*는 의도만 기록, cluster 간 단일 머지 baseline 강제 X.
FIX: 매 머지 후 mandatory rebase-on-current-develop + affected 전체 테스트 (PR 전 한 번이 아님).
2. JSON artifact가 거짓 권위가 됨HIGH-2
WHAT BREAKS
CONDUCTOR가 stale/partial JSON 읽고 "verified" 마킹 → human 의심 skip → 잘못된 state로 후속 작업 라우팅.
WHY DESIGN FAILS
artifact가 coordination state로 취급되는데 schema/version/checksum/source-commit 계약 없음.
FIX: 모든 artifact에 base_sha, head_sha, schema_version, producer_role, verification_command 필수. base 이동 시 자동 expire.
3. Reviewer/Verifier split → 책임 공백HIGH-3
WHAT BREAKS
REVIEWER는 design/product fit, VERIFIER는 command 통과 확인. "integrated behavior 실제로 동작하는가" 소유자 없음.
WHY DESIGN FAILS
역할 분리가 throughput 최적화는 했으나 accountability diffuse.
FIX: 이슈당 explicit Release Captain 1명: "I own merge readiness". green artifact 있어도 reject 권한.
4. cmux pane이 실패한 agent 숨김HIGH-4
WHAT BREAKS
한 pane이 block/loop/wrong branch 편집/silent stop → CONDUCTOR가 진행 중으로 가정하고 dependent work 스케줄.
WHY DESIGN FAILS
Pane visibility는 operational, stateful 아님. Human이 터미널 스캔하는 건 scale X.
FIX: Pane당 heartbeat artifact: branch, last commit, current task, blocked/unblocked, dirty status, last verification timestamp.
5. Visual gate가 잘못된 제품 certifyMED-5
WHAT BREAKS
VISUAL이 스크린샷만 비교 → behavior/API state는 broken. responsive/permission/error state 누락.
WHY DESIGN FAILS
Visual review를 frontend 완성도로 oversell하기 쉬움.
FIX: Visual pass 단독으론 close 불가. 터치된 create/edit/error/empty/permission state를 cover하는 interaction script와 짝.
6. .review/가 second codebase 됨MED-6
WHAT BREAKS
plans/deviations/dashboards/reviews가 source와 드리프트. Agent들이 live code 대신 review doc 따라감.
WHY DESIGN FAILS
삭제/archival 정책 X, "superseded by commit X" 마커 X.
FIX: 모든 .review artifact에 lifecycle: draft | active | superseded | final + linked commit/PR. CONDUCTOR는 superseded 무시.
7. Workflow tax > 구현 속도 (아이러니 실패)CRIT-7
WHAT BREAKS
Agent들이 JSON/대시보드/pane summary/리뷰 만드는 데 코드 짜는 것보다 더 시간 씀.
WHY DESIGN FAILS
저위험 변경에도 모든 역할이 mandatory처럼 보임.
FIX: Risk-tier 라우팅. Tiny 변경 = CODEX + VERIFIER만. Full cluster = migrations/cross-module contracts/shared UI shells/auth/permissions/prod data path만.

CLAUDE 적대적 분석 6 추가 risks (codex 미언급)

8. CODEX abort = 작업 통째로 손실CRIT-A
WHAT BREAKS
"abort no-commit + BLOCKER.md" 룰 — codex가 20분 구현 중 ambiguity 발견 → 모든 진행 상태 증발. 3~4번 반복되면 dev 속도 이득 사라짐.
WHY DESIGN FAILS
codex는 비대화형. "save partial?" 못 물음. 그냥 stop.
FIX: abort 전 .review/ISSUE-N-PARTIAL.diff에 working tree stash. ARCHITECT가 pickup 가능. 또는 WIP branch로 commit 후 abort.
9. CONDUCTOR context overflow (1M도 무한 아님)CRIT-B
WHAT BREAKS
수 주 누적된 phase summary가 1M context 채움 → 자동 truncation → 오래된 결정 손실. 복구하려면 모든 .review/*.json에서 재구성 (수 시간).
WHY DESIGN FAILS
CONDUCTOR는 single session으로 설계됨. context 한계 + 회복 story 없음.
FIX: 강제 룰 — N일마다 또는 N cluster마다 CONDUCTOR session rotate. State는 100% .review/PHASE-SUMMARY-*.json에서 재구성 가능해야 함 (in-memory state 금지).
10. ARCHITECT가 review-reject loop bottleneckHIGH-C
WHAT BREAKS
REVIEWER → ARCHITECT 프록시 룰 (D6) 때문에 매 reject마다 ARCHITECT가 review.json 읽고 patch prompt 재작성. 3 cluster 병렬 × 다중 reject = ARCHITECT context 폭발.
WHY DESIGN FAILS
"single authority" 룰이 single bottleneck 만듦. CONDUCTOR 도입 의도와 모순 (context rot 방지).
FIX: REVIEWER가 review.json에 patch_instructions 필드 직접 작성. ARCHITECT는 rubber-stamp 후 forward. 또는 minor patch는 REVIEWER → CODEX 직접 (룰 완화).
11. codex sandbox = danger-full-accessCRIT-D
WHAT BREAKS
현재 transcript에 sandbox: danger-full-access 확인됨. CODEX가 worktree 밖 임의 파일 편집/삭제 가능. 잘못된 prompt → ~/, ../, 시스템 파일 손상. supply chain 공격 시 치명적.
WHY DESIGN FAILS
워크플로우는 codex의 자율성 전제. 현재 모드는 자율성 + 무제한 권한 = 위험.
FIX: codex 호출 시 --sandbox workspace-write + --cwd <worktree> 강제. 워크트리 외부는 read-only.
12. cmux 자체가 SPOFHIGH-E
WHAT BREAKS
cmux 크래시 → 모든 pane 상태 손실. 진행 중 cluster orphan. Codex 세션도 죽음.
WHY DESIGN FAILS
워크플로우 state가 pane(메모리) + .review/(디스크) 양쪽에 분산. pane state는 휘발성.
FIX: Hard rule — cmux pane = UI only. 모든 critical state 즉시 .review/*.json으로 flush. Pane 재생성으로 100% 복구 가능해야 함.
13. 도구·스키마 버전 드리프트 mid-clusterMED-F
WHAT BREAKS
cluster 진행 중 CONDUCTOR/codex/스키마 업그레이드 → in-flight v1 artifact를 v2로 잘못 해석.
WHY DESIGN FAILS
schema_version 필드는 있지만 migration story 없음. cross-version read 허용 시 silent corruption.
FIX: Cluster dispatch 시 schema version + 도구 버전 lock. cross-version read 금지 (refuse + alert).

필수 가드레일 v0.3 추가 사항

Pre-trial-run 필수 5개:
  1. Risk tier routing 룰 명시 — P3 trivial = CODEX+VERIFIER 2-pane만. Full cluster = migration/auth/shared-UI/permissions/prod-data 한정.
  2. Release Captain 역할 추가 (CONDUCTOR 겸임 권장) — 모든 green에도 reject 권한.
  3. Codex sandbox lock — 모든 codex 호출에 --sandbox workspace-write --cwd <worktree> 강제. 호출 wrapper 스크립트 작성.
  4. Partial work 보존 — CODEX abort 시 .review/ISSUE-N-PARTIAL.diff 강제 저장 (worktree stash).
  5. Rebase-after-merge hook — 한 cluster 머지 후 모든 in-flight worktree에 rebase 자동 실행 + affected test 재실행.
Pre-week-1 필수 5개:
  1. Artifact 계약 강화 — 모든 JSON에 base_sha, head_sha, producer_role, verification_command 필수. base 이동 시 expire.
  2. Lifecycle field on .review/* — draft | active | superseded | final.
  3. Pane heartbeat — pane당 .review/PANE-<id>-HEARTBEAT.json 주기 update. stale 감지 → CONDUCTOR alert.
  4. CONDUCTOR session rotate 룰 — N일/N cluster 후 rotate. state는 disk artifact에서 재구성.
  5. REVIEWER patch_instructions 필드 — ARCHITECT가 rubber-stamp만, bottleneck 완화.

최종 판정 워크플로우 적합성

방향성 OK. Dev 속도 + 장기 안정성 + 안정적 운영 목표에 부합.

단, 위 5+5 가드레일 없이 trial run = 실패 확률 높음. 특히 #1 (semantic 충돌) #2 (workflow tax) #4 (codex abort 손실)는 첫 cluster에서 즉시 드러날 가능성 70%+.

권장: Trial 전 위 "Pre-trial-run 필수 5개"만이라도 구현. 나머지는 trial 중 마찰 관찰 후 v0.3에 통합.
